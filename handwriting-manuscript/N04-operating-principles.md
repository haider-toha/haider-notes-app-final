operating principles

users before opinions
i’ll trade a clever architecture for a workflow
that actually unblocks the user.

document the 'why'
code tells you what. decisions tell you why.
i write adrs for one-way doors so future-me
isn’t guessing.

optimise for reversibility
speed comes from confidence. i build systems where
deploys are boring and rollbacks are instant. one-way
door = slow down. two-way door = move
now.

make it observable
if it can’t be debugged quickly, it isn’t
done. clear failure modes, good logs and metrics
are part of the feature.

strong opinions, loosely held
i’ll argue for a decision with the data
i have. better data wins immediately.
